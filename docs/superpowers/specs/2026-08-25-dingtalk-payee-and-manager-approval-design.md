# 钉钉收款人与总经理审批映射设计

## 背景

出纳工作台中的钉钉导入记录存在两处字段映射缺失：

- 钉钉表单字段 `收款人beneficiario` 已被解析，但当前只写入“收款账号”，导致“收款人名称”列为空。
- 钉钉流程中的 CEO 或总经理级审批已经通过，但同步逻辑只保存流程事件，没有将结果反映到请款记录的“总经理审批”字段。

## 目标

1. 将中文字段和列标题“收款人名称”统一改为“收款人”，西语仍使用 `Nombre del beneficiario`。
2. 新导入的钉钉记录将 `beneficiario` 同时写入“收款人”和“收款账号”。
3. 已有记录在同步钉钉流程时，仅为空字段补入 `beneficiario`，不覆盖人工内容。
4. 钉钉 CEO 或总经理级节点最近一次审批为通过时，仅在“总经理审批”为空的情况下自动写入“同意付款”和审批日期。
5. 人工填写的总经理审批结论和收款信息始终优先。

## 数据映射

### 收款人

钉钉来源的标准化映射结果增加明确的 `beneficiary` 元数据：

- 初次导入：`payee_name = beneficiary`，`payee_account = beneficiary`。
- 后续同步：当 `payee_name` 为空时补入 `beneficiary`；当 `payee_account` 为空时补入 `beneficiary`。
- 任一目标字段已有值时保持原值，不因钉钉同步而覆盖或清空。
- 多个 `beneficiario` 值沿用现有去重并以 ` / ` 连接的规则，同时保留“存在多个收款人，请确认”警告。

### 总经理审批

从标准化的钉钉流程事件中识别总经理级审批节点。节点名称仅匹配明确的管理层称谓：

- `CEO`
- `总经理`
- `Gerente General`
- `Dirección General` / `Direccion General`

普通“经理”“部门经理”“采购经理”等不匹配。

处理步骤：

1. 仅考虑正常审批任务事件，并按事件时间和流程顺序排序。
2. 取最近一次总经理级节点事件。
3. 最近一次结果为 `AGREE` 时，生成自动结论“同意付款”，审批日期取该事件的实际发生日期。
4. 如果请款记录的 `general_manager_approval` 已有人工结果，则结论和日期均不自动改写。
5. 最近一次事件不是 `AGREE`、事件时间缺失或无法唯一匹配流程时，不自动填写。

## 同步行为

字段补齐发生在现有“同步钉钉流程”事务中，与流程元数据、审批事件和附件状态一并提交。任何外部查询失败、版本冲突或事务失败都不应产生部分字段更新。

同步后继续沿用现有的请求状态快照、审计记录和批次版本机制。再次同步必须幂等：已经补齐的值保持不变，人工修改后的值不会被恢复成钉钉值。

## 界面

所有中文界面、列设置和详情表单中面向用户的“收款人名称”改为“收款人”。内部字段名 `payee_name` 不变，以避免数据库迁移和接口破坏。西语文案保持 `Nombre del beneficiario`。

## 测试

- 导入映射测试：`beneficiario` 同时进入 `payee_name` 与 `payee_account`。
- 同步测试：空白收款字段被补齐，已有人工值不被覆盖。
- 流程识别测试：CEO、总经理和西语总经理节点的最近一次 `AGREE` 可生成“同意付款”及日期。
- 反例测试：部门经理节点、最近一次非通过结果、已有人工审批结果均不自动改写。
- 前端测试：中文显示“收款人”，不再显示“收款人名称”。
- 回归测试：后端、前端及生产构建全部通过。

## 发布与已有数据

不执行无法区分人工值的盲目数据库迁移。部署后，对草稿批次执行一次“同步钉钉流程”即可按来源数据补齐已有空白字段；已归档或不再允许同步的批次保持不变，避免绕过现有业务约束。
