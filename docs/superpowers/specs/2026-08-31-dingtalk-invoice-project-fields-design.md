# 钉钉发票与项目字段同步设计

## 背景

钉钉支出审批新增了以下表单字段：

- `是否有发票 / Existe factura?`
- `项目归属 / Pertenencia del proyecto`

系统已有“账户性质”与“项目归属”字段，无需新增数据库字段。当前从支出中间表导入及后续“同步钉钉流程”尚未统一读取这两个表单字段。

## 目标

1. 根据钉钉“是否有发票”自动推导账户性质：
   - 明确表示有发票时写入“公户”；
   - 明确表示无发票时写入“私户”；
   - 空值或无法识别的值不做推断。
2. 将钉钉“项目归属”原文写入系统项目归属字段。
3. 新导入和已有记录同步采用相同的解析规则。
4. 保留系统内已有的人工填写结果，只补齐空白字段。

## 字段识别与标准化

在统一的钉钉表单解析层增加两个标准化结果：`payment_account` 和 `project`。

表单标题按不区分大小写的前缀匹配处理，兼容中西文组合标题：

- 发票字段：`是否有发票`、`Existe factura`
- 项目字段：`项目归属`、`Pertenencia del proyecto`

发票值在去除首尾空白并忽略大小写、重音差异后进行保守识别：

- 有发票：`是`、`有`、`有发票`、`Sí`、`Si`、`Yes` → `公户`
- 无发票：`否`、`无`、`无发票`、`No` → `私户`
- 其他值：不生成账户性质

项目归属保留钉钉表单中的显示文本，不额外拆分或翻译。采购中间表已有 `project_name` 时，钉钉表单值优先；钉钉项目字段为空时继续使用现有中间表值。

## 数据流

### 从中间表新导入

标准支出与月结支出都通过统一映射函数读取表单字段。生成新请款记录时：

- `payment_account` 使用标准化后的“公户/私户”；
- `project` 使用钉钉项目值，钉钉未填写时使用当前中间表项目值；
- 无法识别的发票值不阻止导入，也不产生账户性质。

### 同步已有请款

钉钉元数据查询返回标准化的 `payment_account` 和 `project`。同步时仅在以下条件全部满足时补齐：

- 钉钉单号唯一匹配到一条来源记录；
- 系统对应字段当前为空；
- 钉钉解析结果有效且非空。

系统字段已有内容时，无论其来源是人工录入、Excel 导入还是历史同步，都保持不变。来源冲突、未匹配或字段值无法识别时不修改业务字段。

## 审计与错误处理

- 继续使用现有同步事务与版本冲突保护。
- 字段补齐与本次钉钉同步一并写入现有审计历史，保留更新前后的业务字段值。
- 表单字段缺失或值无法识别属于可接受情况，不令整次同步失败。
- 中间表读取失败时沿用现有错误响应，不进行部分写入。
- 重复执行同步应保持幂等：第一次补齐后，后续同步不再修改该字段。

## 测试范围

后端测试覆盖：

- 中西文组合字段标题；
- “是/有发票/Sí/Si/Yes”映射为“公户”；
- “否/无发票/No”映射为“私户”；
- 空值、未知值不推断；
- 项目归属原文读取及采购中间表回退；
- 新导入同时写入账户性质和项目归属；
- 已有记录同步补齐空白字段；
- 人工填写结果不被覆盖；
- 未匹配、重复来源不修改字段；
- 重复同步不产生业务字段变化；
- 审计历史包含补齐前后的字段值。

前端无需新增交互或数据库迁移；现有表格列、筛选和编辑能力继续使用。

## 发布与验收

1. 运行相关后端测试、全量后端测试、前端测试和生产构建。
2. 合并到本地 `main` 并推送。
3. 停止生产服务并备份真实数据库，校验备份完整性。
4. 部署新版本、启动服务并确认健康状态。
5. 在线触发一次钉钉同步，抽查：
   - 新审批正确生成“公户/私户”；
   - 项目归属正确带入；
   - 已有人工值没有变化；
   - 服务日志无新增错误。

## 非目标

- 不根据发票附件是否存在进行推断；只使用钉钉“是否有发票”字段。
- 不覆盖人工填写的账户性质或项目归属。
- 不修改“是否开具发票/开票情况”字段。
- 不增加数据库字段或迁移。
