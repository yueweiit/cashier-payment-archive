# 墨西哥审批可用性与中国应付隔离修复设计

## 1. 背景与目标

墨西哥审批跟进功能已经具备流程发现、本地缓存、审批人展示、附件同步和中西双语界面，但上线核对发现五个可用性与口径问题：

1. 审批列表使用固定小列宽，公司、摘要、节点和审批人被明显挤压。
2. 审批状态虽然先于附件写入本地，但前端只在整批附件完成后刷新，造成“必须等所有附件才能看审批”的误解，且无法优先加载某一单。
3. 西语导航文案较长，当宽度不足时仅使导航区横向滚动并隐藏滚动条，用户无法知道右侧仍有选项。
4. 中国工作台和每日应付的地区隔离受一个默认为关闭、且前端无法开启的设置控制，上线数据仍可包含墨西哥记录。
5. 地区解析将“执行地区=墨西哥、Sheet=中国”当成冲突待核对，与已确认的“执行地区优先，Sheet 仅缺失时兜底”规则不符。

本次修复的目标是：

- 审批状态写入后立即可见，不受全量附件下载时间影响。
- 每条流程清楚展示所有当前正在等待操作的审批人。
- 用户可手动加载或优先加载某一条流程的附件。
- 列表在常见桌面宽度下不挤压，西语导航始终具有可发现性。
- 中国工作台、每日应付、统计和默认导出固定只包含已确认为中国的记录。
- “悦为智能 + 执行地区墨西哥”等记录被正确归为墨西哥，不进入中国口径。

## 2. 根因

### 2.1 列表布局

`.mexico-tracking-table` 使用 `table-layout: fixed`，同时将公司、申请人、当前节点和当前审批人限制在 150–190px。表格容器在桌面宽度下使用 `overflow: hidden`，而最小表格宽度只在屏幕小于 1280px 时才生效。这使长公司名、西语摘要和长审批人名被强制塞入狭窄单元格。

### 2.2 状态刷新被附件阻塞

后端已在 `committing_state` 阶段提交流程状态，附件查询与下载随后执行。前端轮询却只在整个任务进入 `completed` 后调用 `refreshAll()`，因此用户在长时间附件下载期间看到的仍是旧审批缓存。

### 2.3 当前待办人丢失

`_current_workflow_task` 仅选取最新的一个活跃任务，然后仅保留该任务的第一个处理人。这会丢失会签、并行节点和单任务多处理人信息。节点名缺失时，列表只显示破折号。

### 2.4 导航不可发现

导航容器在文案过长时横向滚动，但滚动条被强制隐藏。账户与退出区域保持固定宽度后，导航右侧项目会被裁掉，且没有“更多”提示。

### 2.5 中国口径未生效

`china_region_isolation_enabled` 默认值为 `false`，且当前设置对话框没有对应开关。每日应付和工作台因此默认不执行地区过滤。同时，`resolve_region` 在明确执行地区与 Sheet 映射不同时返回 `review`，违反执行地区优先级。

## 3. 已选方案与备选方案

采用“精准修复现有架构”方案：保留现有墨西哥跟进缓存与全量同步能力，修正地区口径，将审批状态与附件下载在任务展示上解耦，使用结构化当前待办任务，并对表格与导航做针对性响应式改造。

未采用的方案：

- 仅修改 CSS 和前端刷新时机：改动小，但无法正确保留并行待办人，也不能支持真正的单行附件优先。
- 取消全量附件同步，全部改为按需下载：同步最快，但会失去完整的后台附件归档，不符合既有目标。

## 4. 地区判定与中国口径

### 4.1 地区优先级

地区解析按以下顺序执行：

1. 外部来源的 `execution_region` 明确为中国或墨西哥时，直接采用该地区。
2. `execution_region` 缺失或无法识别时，若存在管理员人工确认，保留人工结论。
3. 仍未定类时，使用精确 Sheet 映射。
4. 上述信息均无法确认时，进入 `review`。

Sheet 与明确执行地区不同时，保留 Sheet 事实用于审计，但不再将记录改判为 `review`。因此“悦为智能 YW Tech_Ai + 执行地区墨西哥”必须解析为 `mexico`。

### 4.2 中国数据隔离

中国工作台、批次数量与金额、付款进度、每日应付摘要/明细/趋势和默认导出都必须固定使用：

```text
resolved_region = 'china' AND region_review_status = 'resolved'
```

该规则不再由 `china_region_isolation_enabled` 决定。为了兼容旧数据与旧客户端，设置键可在一个版本内保留，但迁移会将其固定写为 `true`，后端不再允许通过设置接口关闭。

### 4.3 现有数据迁移

迁移对所有现有 `payment_requests` 重新执行地区解析。地区发生变化的请款：

- 更新当前请款的地区字段。
- 追加 `request.region_reclassified` 应付历史版本，生效时间为迁移执行时间。
- 写入审计汇总，记录中国、墨西哥、待核对数量及变更数量。

历史版本保持只追加，不回写过去日期的快照。修正当天和以后的每日应付使用新分类，过去日期保留当时已记录结果。

## 5. 当前待办任务

### 5.1 数据模型

新增 `mexico_approval_current_tasks` 表，一行表示一个活跃任务上的一个当前待办人：

- `id`
- `approval_no`
- `task_key`（流程实例、任务标识和待办人的稳定组合）
- `task_id`、`activity_id`
- `node_name`
- `approver_id`、`approver_name`
- `entered_at`
- `synced_at`、`created_at`、`updated_at`

`approval_no + task_key` 建立唯一约束，`approver_id/approver_name` 和 `node_name` 建立索引。每次流程状态提交时，在同一个 SQLite 事务内用新的活跃任务集合替换该审批的当前任务。

`mexico_approval_tracking` 现有单值字段在兼容期内保留，但改为派生摘要：审批人按去重后的名称连接，节点按去重后的节点名连接，节点进入时间取最早活跃待办的时间，使预警反映最长等待时间。

### 5.2 解析规则

- 保留所有状态为 `RUNNING`、`PROCESSING` 或 `PENDING` 的任务。
- 一个任务有多个处理人时，为每个处理人生成待办记录。
- 节点名优先使用任务字段，其次使用同 `activity_id` 的流程事件，仍缺失时显示“待审批节点 / Etapa pendiente”。
- 人员名称无法映射时保留原始用户 ID，对外显示“未识别人员（ID）”。

### 5.3 API 与催办

列表和详情接口新增：

- `current_tasks`：当前待办任务列表。
- `current_approvers`：去重后便于直接展示的待办人列表。
- `current_nodes`：去重后节点列表。

按审批人和节点筛选使用当前任务表的 `EXISTS` 条件，不依赖连接后的摘要字符串。中西双语催办内容列出所有当前待办人。

## 6. 审批状态与附件解耦

### 6.1 状态立即可见

`mexico_sync_runs` 新增 `state_committed_at`。发现结果、流程状态、事件和当前待办在短 SQLite 事务内提交后，立即写入该时间。

前端轮询首次看到新的 `state_committed_at` 时立即刷新列表、概览和已打开的详情。后续附件进度更新不重复刷新全表。

界面明确分开展示：

- “审批状态已更新”。
- “附件正在后台处理 x/y”。

附件查询或下载失败不会将已提交的审批状态标记为失败。

### 6.2 共享附件队列

保留全量附件归档，但将附件下载从流程状态任务中拆为共享后台队列。`mexico_approval_attachments` 增加：

- `priority`：普通全量候选为 0，用户指定行为 100。
- `requested_at`：最近一次人工请求时间。
- `claim_token`、`claimed_at`：工作线程的原子认领信息。

附件工作器每次只按 `priority DESC, requested_at ASC, id ASC` 取少量记录，并在下载前使用条件更新认领。这允许用户在全量队列运行时将某一单提升到下一批，也防止全量任务与单行任务重复保存。超时认领可在安全时间后重试。

### 6.3 单行附件 API

新增：

```text
POST /api/mexico-tracking/{tracking_id}/attachments/sync
```

接口会：

1. 执行权限检查并解析 `approval_no`。
2. 对该流程补查附件清单，幂等写入附件候选。
3. 将该流程所有未完成附件提升为人工优先级。
4. 复用正在运行的附件工作器；若没有工作器，启动一个。
5. 返回该行的总数、已就绪、排队中、下载中和失败数。

重复点击只更新优先级和请求时间，不会创建重复附件。失败记录可由该接口单行重试。

## 7. 页面与交互

### 7.1 审批列表

桌面列表使用明确的最小宽度和可见横向滚动，不再将所有列强制压缩到容器宽度。建议列宽：

- 预警：90px。
- 钉钉单号：210px。
- 子公司：240px。
- 申请人：180px。
- 摘要：最小 320px。
- 当前节点：200px。
- 当前待办人：最小 240px。
- 停留：110px。
- 操作：140px。

表格容器使用 `overflow-x: auto`并保留浏览器滚动提示。子公司、摘要和待办人允许合理换行；单号、停留天数和操作不换行。低于现有移动断点时继续使用卡片视图。

当前待办人使用人名标签展示；多人会签不截断为单人。“当前节点”与“当前待办人”优先于附件信息展示。

### 7.2 详情与单行附件

列表行主操作改为明确的“查看审批 / Ver aprobación”。详情抽屉顶部依次展示：

1. 当前状态、节点和所有待办人。
2. 双语催办。
3. 申请信息和时间线。
4. 附件区。

附件区显示该行的“未加载、排队中、加载中、部分失败、已完成”状态，并提供“加载此单附件 / Cargar archivos de esta solicitud”。按钮只刷新当前详情的附件状态，不刷新整页列表。

### 7.3 西语导航

导航项由统一配置数组渲染。使用 `ResizeObserver` 监测可用宽度，预留“更多 / Más”按钮宽度后，将放不下的项目收入菜单。

- 顶部导航不再使用隐藏滚动条的横向滚动。
- 只要有项目被收起，“更多 / Más”必须可见。
- 当前页面在菜单内时，“更多”按钮保持选中状态，并在可用宽度允许时显示当前页面名称。
- 菜单支持键盘打开、方向键、Escape 关闭和点击外部关闭。
- 用户、语言和退出区域继续保持不重叠。

## 8. 错误处理与一致性

- 流程状态提交后，附件查询或下载失败仅影响附件状态。
- 单行附件请求的外部查询失败保留现有附件和缓存，并在该行显示可重试的简短错误。
- 附件认领使用条件更新和令牌，只有当前认领者可以写入成功或失败结果。
- 人员映射部分失败时，已识别人员仍正常保存，未识别人员保留 ID。
- 当前待办替换、事件更新和跟进主记录更新使用同一事务，不会出现列表审批人与详情待办任务不一致。
- 地区迁移、应付历史追加和设置固化在同一 SQLite 迁移事务中完成。

## 9. 测试与验收

### 9.1 地区与应付

- 执行地区明确为墨西哥且 Sheet 为“悦为智能 YW Tech_Ai”时，解析结果为 `mexico`。
- 执行地区缺失时仍可通过精确 Sheet 映射到中国或墨西哥。
- 旧设置为 `false` 的数据库升级后也固定执行中国隔离。
- 工作台、批次概览、每日应付摘要/明细/趋势与默认导出均排除墨西哥和待核对数据。
- 地区重分类只追加新的应付历史版本，不修改旧版本。

### 9.2 当前待办

- 单任务单审批人、单任务多审批人和多个并行活跃任务都完整保存。
- 完成或被撤回的活跃任务在下次同步后从当前待办中移除。
- 审批人与节点筛选可命中任一当前待办。
- 未识别人员返回原始 ID，催办内容包含所有当前待办人。

### 9.3 同步与附件

- `state_committed_at` 写入后，前端立即刷新状态，附件任务仍在运行。
- 附件失败不回滚或隐藏审批状态。
- 单行请求将该行附件提升为下一批，不需等待全量队列结束。
- 重复点击、全量任务与单行任务并发、失败重试均不产生重复附件或文件对象。

### 9.4 布局与导航

- 在中文和西语下分别以 1280、1512 和 1920 CSS 像素宽度检查顶部导航。
- 任何时候都不得有不可见且没有“更多 / Más”入口的导航项。
- 在同样的桌面宽度下使用长公司名、西语摘要、多待办人和长用户名数据检查列表。
- 列表内容不互相覆盖，横向滚动入口可见，待办人与操作不被截成无法识别的内容。
- “更多”菜单通过鼠标和键盘都可完成打开、选择和关闭。

## 10. 发布策略

1. 在备份 SQLite 主库后执行 schema 和地区重分类迁移。
2. 记录迁移前后中国、墨西哥和待核对请款数，单独核对“悦为智能”中执行地区为墨西哥的记录。
3. 运行一次墨西哥状态同步，核对当前待办人和 `state_committed_at` 时机。
4. 在附件队列运行时手动优先一条流程，确认该行先于普通队列完成。
5. 用中文和西语在实际桌面浏览器中执行布局验收。
6. 上线后观察状态同步耗时、附件队列长度、单行优先耗时、附件失败数和地区重分类数量。

本次继续使用现有 FastAPI、SQLite、React 和进程内线程池，不引入 Redis、Celery 或独立工作进程。
