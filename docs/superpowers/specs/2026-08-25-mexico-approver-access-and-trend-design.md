# 墨西哥审批重构、审批人统计与趋势交互设计

## 背景

现有墨西哥审批桌面表格通过扩大最小宽度缓解了列挤压，但仍存在长公司名导致行高失控、审批人靠近视口边缘被截断、信息层级不清晰的问题。每日应付页面同时使用一个 `selectedDate` 控制当天数据和趋势查询结束日期，点击历史趋势节点后会重新请求截止该日的趋势，从而让更晚的节点消失。

此外，墨西哥审批需要新增按当前审批人汇总的工作负载视图，并建立独立于中国 Sheet 权限的墨西哥流程访问控制。权限必须能表达全量访问、仅查看本人参与流程和禁止访问三种范围。

## 目标

1. 将墨西哥审批桌面列表改为紧凑、可快速扫描的任务表，同时保留全部当前审批人。
2. 在同一墨西哥审批模块内提供“审批列表 / 审批人统计”双标签切换。
3. 按当前审批人展示待审批、已超时、严重超时数量，并支持一键进入已过滤列表。
4. 让点击每日应付趋势节点只切换当天数据，不改变已经展示的 14 日趋势范围。
5. 为墨西哥流程建立按账号和钉钉姓名判断的独立访问范围，并为确认的审批人开通账号。
6. 保持中国工作台、每日应付统计口径、付款、归档和既有 Sheet 权限逻辑不变。

## 非目标

- 不修改墨西哥流程的同步来源、预警阈值算法或附件下载逻辑。
- 不引入钉钉单点登录。
- 不用墨西哥权限替代中国工作台现有的角色和 Sheet 权限。
- 不为“未识别人员”创建共享账号。

## 墨西哥审批信息架构

墨西哥审批仍是顶层导航中的一个目的地。模块英雄区下方增加稳定的双标签：

- **审批列表**：KPI、筛选器、紧凑任务表和审批详情。
- **审批人统计**：显示当前待审批工作负载，点击审批人后自动切换回审批列表。

标签切换不离开墨西哥审批路由。同步状态、预警设置和英雄区保持共享。审批人统计加载失败时只在统计区域显示错误和重试按钮，不清空已加载的审批列表数据。

### 紧凑任务表

桌面表格由九列合并为六列：

1. 预警
2. 审批单
3. 申请信息
4. 摘要
5. 当前待办
6. 停留 / 操作

“申请信息”合并申请人与公司；“当前待办”合并当前节点与全部当前审批人。公司和摘要最多显示两行，超出后省略，`title` 与审批详情提供全文。审批人不得截断或只显示第一人；多人并行时逐个显示并允许在当前待办列内换行。

表格目标最小宽度约 1400px，使约 1512 CSS 像素宽的桌面窗口能直接看到操作列。严重超时不再整行铺浅红背景，改用左侧预警色条和小型预警标签。980px 以下继续使用现有卡片布局。

## 审批人统计

统计数据只覆盖当前仍在运行且属于墨西哥、地区已确认的审批。每个审批人按钮展示：

- **待审批**：该审批人当前被指派的去重流程数。
- **已超时**：预警等级为黄色或红色的流程数。
- **严重超时**：预警等级为红色的流程数。

同一流程有多个当前审批人时，每个人各计一条；同一审批人在同一流程存在多个当前任务时只计一次。预警等级继续使用管理员配置的黄色和红色天数阈值，并与审批列表保持一致。按钮按严重超时数量降序，其次按已超时、待审批和姓名排序。

点击审批人按钮后：

1. 切换到审批列表标签。
2. 将筛选器和已应用筛选中的当前审批人设置为该姓名。
3. 回到第一页并刷新列表。
4. 显示可清除的当前审批人筛选状态。

上方黄色或红色 KPI 按钮在应用预警筛选时保留当前审批人，使审批人和预警能够组合过滤。“全部审批人”清除审批人条件，但不更改其他已应用条件。

统计接口返回当前账号可见范围内的统计。全量权限账号看到所有审批人；仅本人参与账号只会基于其有权查看的流程统计，因此不会通过数字泄露不可见流程。

## 每日应付趋势日期

前端使用两个日期状态：

- `selectedDate`：控制顶部汇总、币种卡片和当天明细。
- `trendEndDate`：控制 14 日趋势查询的结束日期。

初始进入页面时两者都是当天。用户手动修改顶部日期输入时，同时更新两者，保留现有的历史日期查询行为。用户点击趋势节点时只更新 `selectedDate`，不更新 `trendEndDate`。因此点击 8 月 24 日后，页面展示 8 月 24 日的汇总和明细，但趋势仍包含原范围内的 8 月 25 日节点，用户可以直接点击回去。

后端每日应付接口、历史快照和统计口径不变。

## 墨西哥访问控制

### 用户字段

`users` 增加两个字段：

- `mexico_access_scope`：`all`、`participant` 或 `none`，默认 `none`。
- `mexico_identity_name`：绑定同步数据中的钉钉姓名；全量权限账号可以为空，参与者权限账号必须填写。

系统管理员始终视为 `all`，避免旧管理员在迁移后失去访问。其他账号严格使用字段值。身份姓名比较采用去除首尾空白后的精确比较，不做模糊匹配，避免姓名相近导致越权。

### 可见流程定义

`all` 可以查看全部墨西哥流程。`participant` 仅能查看其绑定姓名出现在以下任一位置的流程：

- `mexico_approval_tracking.applicant_name`
- `mexico_approval_current_tasks.approver_name`
- `mexico_approval_events.operator_name`，包含审批处理人和抄送人

`participant` 缺少身份绑定时按无权限处理。`none` 不显示墨西哥导航，所有墨西哥接口返回 403。详情接口、列表、历史、筛选选项、汇总、审批人统计和附件单行同步都使用相同可见条件，禁止通过直接 ID 或统计接口绕过权限。

预警设置和地区确认仍只允许管理员修改。同步钉钉审批继续沿用现有已登录角色要求，但同步后的读取范围按上述规则执行。

为保证参与者条件查询稳定，增加申请人、事件处理人所需索引；现有当前审批人任务索引继续复用。

### 管理界面

用户管理的创建和编辑表单增加墨西哥权限范围及钉钉姓名字段。选择“仅本人参与”时钉钉姓名为必填；选择“不可访问”时不展示墨西哥导航。接口验证非法范围并在缺少绑定时拒绝保存参与者权限。

## API 与数据流

新增审批人统计只读接口，例如 `GET /api/mexico-tracking/approver-stats`，返回：

```json
{
  "items": [
    {
      "approver_name": "PEREZ.MOLINA.ANGELICA",
      "pending": 68,
      "overdue": 64,
      "severe": 51
    }
  ]
}
```

统计服务复用列表的墨西哥待审批条件、账号可见条件和预警设置。权限条件由一个共享辅助函数生成，列表、统计、筛选选项、汇总和详情不得各自复制不同版本。前端同步完成后同时刷新列表、KPI、筛选选项和审批人统计。

用户公开模型、登录返回值、管理员用户创建与更新接口增加墨西哥字段。密码哈希继续使用现有安全模块。

## 错误处理与审计

- 无墨西哥权限返回 403；无权查看特定流程的详情使用 404，避免暴露流程是否存在。
- 参与者权限缺少钉钉姓名时拒绝保存；历史脏数据按无权限处理。
- 账号开通脚本输出新增、更新、跳过和冲突数量，不输出密码哈希。
- 创建账号和修改权限写入现有用户审计日志；部署脚本对现有账号不重置密码。
- 统计加载失败时保留页面结构并提供重试，不影响审批列表和同步操作。

## 测试与验收

### 后端自动化

- 全量、参与者、无权限三种范围分别验证列表、汇总、筛选选项、统计、详情和附件入口。
- 参与者通过申请人、当前审批人、历史处理人和抄送人四种路径获得访问。
- 不相关流程不可见，直接详情 ID 返回 404。
- 多人并行流程分别计入每个人；同人多任务按流程去重。
- 已超时等于黄色加红色，严重超时等于红色，并响应自定义预警阈值。
- 管理接口拒绝非法权限范围及缺少姓名的参与者配置。
- 开通脚本重复执行不新增重复账号、不修改 Tiffany 和施鸣坤密码。

### 前端自动化与浏览器验收

- 双标签、审批人统计按钮、点击后返回列表及组合预警筛选。
- 六列桌面表格、约 1400px 最小宽度、公司和摘要两行截断、全部审批人保留。
- 无权限账号不显示墨西哥导航。
- 点击 8 月 24 日趋势点后，8 月 25 日点仍存在，汇总和明细显示 8 月 24 日。
- 手动修改顶部日期仍会重建以该日期结束的 14 日趋势。
- 中文与西语、桌面宽度和小屏卡片模式均无溢出或遮挡。

## 部署

部署前运行完整后端测试、前端测试和生产构建，并备份 SQLite 数据库。部署后执行 schema 初始化和幂等账号开通脚本，再重启服务。使用管理员、全量普通账号和参与者账号分别验收权限边界；确认现有 Tiffany、施鸣坤密码未改变。最后检查服务日志、公开页面响应和迁移字段。
