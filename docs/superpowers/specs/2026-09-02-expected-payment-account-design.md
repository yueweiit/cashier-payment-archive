# 预计支付账户字段设计

## 背景

钉钉支出审批已经包含“是否有发票”字段，系统据此生成现有的“账户性质”（公户/私户）。现在需要新增独立的“预计支付账户”字段，用于指明计划从哪一个公司账户付款。

“预计支付账户”与“账户性质”含义不同，不能复用现有 `payment_account` 字段：

- 账户性质回答“公户还是私户”；
- 预计支付账户回答“预计由哪个主体的公司账户支付”。

## 目标

1. 在请款工作台新增“预计支付账户 / Cuenta de pago prevista”字段。
2. 优先使用钉钉审批中明确填写的“预计支付账户”。
3. 钉钉未填写时，根据审批中的“服务主体”生成默认值。
4. 保护系统内的人工结果，同时允许钉钉明确值替换系统自动生成的默认值。
5. 让新导入、已有记录同步、页面编辑和 Excel 导入导出使用同一套规则。

## 数据结构

在 `payment_requests` 增加两个字段：

- `expected_payment_account TEXT`：预计支付账户的业务值；
- `expected_payment_account_source TEXT`：值的来源，允许：
  - `dingtalk_explicit`：钉钉审批明确填写；
  - `service_subject_default`：根据服务主体自动生成；
  - `manual`：页面或 Excel 人工填写。

数据库升级使用现有兼容迁移机制增加列，不重建或覆盖生产数据。历史记录初始保持空值，不在迁移阶段根据旧字段盲目推断。

## 钉钉字段识别

统一表单解析层新增两个标准化输入：

- 预计支付账户：按不区分大小写的标题前缀匹配 `预计支付账户`、`Cuenta de pago prevista`；
- 服务主体：按标题前缀匹配 `服务主体`，兼容标题后附带西语说明的组合形式。

表单组件继续使用现有显示值解码逻辑，兼容直接字符串、JSON 编码选择项、`name`/`label` 显示值及空白首项。

## 主体映射

仅对已配置的服务主体生成默认值，不对未知主体进行猜测。初始映射及其中英文别名如下：

- 悦为智能 → 悦为智能公司账户；
- 凌翔 → 凌翔公司账户；
- 星铭 → 星铭公司账户；
- 拉丁购 → 拉丁购公司账户；
- YW MOLDES → YW MOLDES公司账户。

匹配时忽略大小写、重音、标点和多余空白，并兼容当前审批中已有的中英文全称、简称及 Sheet 名称。当钉钉“预计支付账户”也为空时，无法识别的新主体才保持预计支付账户为空，并产生非阻断提示“服务主体无法匹配预计支付账户，请人工填写”。

## 取值优先级

对每条钉钉来源记录先计算候选值：

1. 钉钉“预计支付账户”有明确非空值：候选值为原始显示文本，来源为 `dingtalk_explicit`；
2. 钉钉字段为空且服务主体可识别：候选值为主体映射结果，来源为 `service_subject_default`；
3. 两者均不可用：不产生候选值。

“是否有发票”继续只生成现有“账户性质”，不参与预计支付账户的计算。

## 新导入

运营支出、采购支出和月结付款统一输出 `expected_payment_account` 与 `expected_payment_account_source`：

- 钉钉明确值优先；
- 否则使用服务主体默认值；
- 未知主体允许继续导入，但显示人工填写提示；
- 生成的值同时写入顶层映射结果、`request_data` 和 `raw_extra.external_source`，保持不同导入路径一致。

## 已有记录同步

钉钉元数据同步只有在钉钉单号唯一匹配时才处理预计支付账户。规则如下：

- 当前字段为空：写入有效候选值及其来源；
- 当前来源为 `manual`：不覆盖，包括钉钉明确值；
- 当前来源为 `service_subject_default`：
  - 钉钉出现明确值时，用明确值替换，并将来源改为 `dingtalk_explicit`；
  - 只有新的服务主体默认值时，可随服务主体映射结果更新；
- 当前来源为 `dingtalk_explicit`：钉钉明确值发生变化时同步更新；
- 钉钉明确字段后来被清空时，不自动清除已有值，也不降级为服务主体默认值；
- 来源冲突、未匹配或未知主体时不修改业务字段。

重复执行同一同步不得产生额外业务变化或无意义版本更新。

## 人工编辑

- 页面新增、编辑或表格批量保存非空值时，将来源标记为 `manual`；
- Excel 导入的非空值同样视为 `manual`；
- 用户主动清空预计支付账户时，同时清除来源标记；下一次钉钉同步可以重新自动补齐；
- 人工修改写入现有请求审计历史。

## 页面设计

- 工作台表格在“账户性质”后新增“预计支付账户 / Cuenta de pago prevista”；
- 新列默认显示，并纳入“列设置”的排序、隐藏及用户偏好；
- 新增请款和请求编辑器显示可编辑字段；
- 列宽和换行行为沿用现有文本字段；
- 移动端卡片在账户性质附近展示预计支付账户；
- “每日应付”页面和每日应付区间导出不增加该字段。

## Excel 与业务链路

- 工作台“导出全部”和“导出筛选结果”增加中文表头“预计支付账户”；
- 工作台 Excel 导入识别“预计支付账户”，非空值标记为人工来源；
- 复制到下周、换行、合并、归档、恢复及快照处理同时保留字段值和来源；
- API 请求和响应增加该业务字段，来源字段只用于内部同步判断，不作为普通用户的独立可编辑字段；
- 现有 Sheet 权限规则继续适用，不因新增字段扩大数据可见范围。

## 审计与错误处理

- 自动补齐或自动替换记录旧值、新值、旧来源和新来源；
- 人工修改沿用现有请求更新审计；
- 表单字段缺失、值为空或服务主体未知属于非阻断情况；
- 中间表读取失败沿用现有错误响应，不进行部分写入；
- 不修改现有“账户性质”“是否开具发票”“项目归属”字段的含义或同步规则。

## 测试范围

后端测试覆盖：

- 中西文组合字段标题及多种表单显示值结构；
- 钉钉明确预计支付账户优先；
- 五类服务主体的中英文别名映射；
- 未知主体保持为空并返回提示；
- 运营、采购和月结三类新导入；
- 空白已有记录同步补齐；
- 服务主体默认值被钉钉明确值替换；
- 钉钉明确值后续变更；
- 人工值不被覆盖；
- 人工清空后允许重新补齐；
- 未匹配、重复来源和重复同步；
- 审计前后值及来源；
- Excel 导入导出、复制下周、合并、归档和恢复。

前端测试覆盖：

- 新列默认可见及列设置；
- 中西语表头；
- 表格和编辑器人工修改；
- 移动端显示；
- Excel 相关入口保持可用。

## 发布与验收

1. 运行相关后端测试、全量后端测试、前端测试和生产构建。
2. 合并本地 `main` 并推送远端。
3. 停止生产服务，备份真实数据库并执行完整性校验。
4. 部署新版本并确认服务健康。
5. 在线触发一次钉钉同步，抽查：
   - 钉钉明确预计支付账户被优先写入；
   - 钉钉未填写时按已配置服务主体生成默认值；
   - 未知主体未被错误猜测；
   - 人工值没有被覆盖；
   - 账户性质仍由“是否有发票”独立生成；
   - 服务日志无新增错误。

## 非目标

- 不根据是否有发票推断预计支付账户；
- 不复用或改名现有“账户性质”字段；
- 不为服务主体增加管理页面，本期使用代码内受测试保护的映射配置；
- 不在“每日应付”中展示或导出预计支付账户；
- 不自动猜测未知服务主体对应的账户。
