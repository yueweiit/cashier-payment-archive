# 顶部同步提示与 GitHub 拉取部署设计

## 背景

当前全局提示直接渲染在深色导航栏的账户区域中。钉钉流程同步结果包含较长的数量和耗时说明时，提示会参与导航栏的 Flex 布局，导致导航栏增高、按钮换行、退出按钮下沉，破坏页面首屏结构。

## 已确认方案

采用方案 A：导航栏只保留品牌、页面导航、语言、账户和退出；全局提示移动到导航栏外的固定浮层中。

- 浮层位于页面右上角、导航栏下方，不占据文档流。
- 成功提示保留简洁摘要，完整同步结果仍写入现有操作日志。
- 提示支持手动关闭，并在 5 秒后自动消失。
- 长文本限制最大宽度并允许换行，不引起页面横向溢出。
- 手机端浮层占用左右安全间距，不遮挡顶部导航按钮。
- 账户密码修改成功提示复用同一浮层容器。

## 可访问性与交互

- 容器使用 `aria-live="polite"`，同步失败等错误信息使用 `role="alert"`。
- 关闭按钮具有明确的中文/西语标签。
- 新提示出现时重置自动关闭计时；用户切换页面不会把提示重新放回导航栏。

## GitHub 部署约定

本次只修改和验证本地代码，并将提交推送至现有 GitHub 分支，不部署线上。

后续服务器推荐使用“GitHub 拉取式部署”：服务器配置只读 Deploy Key，执行 `git fetch`、切换到经过确认的提交，再运行仓库内的部署脚本。这样服务器不需要保存个人 GitHub 密码，也能避免每次通过浏览器逐文件传输。自动在 `main` 更新后上线暂不启用，防止未经人工验收的提交直接影响 8011。

## 验收标准

- 无论提示多长，桌面导航栏保持单行且高度稳定。
- 提示出现在右上角浮层，5 秒后消失，也可手动关闭。
- 390px 宽度下无整体横向溢出，提示不遮挡主要导航。
- 现有页面切换、退出、修改密码和同步结果提示功能保持正常。
- 前端 TypeScript 检查与生产构建通过。
