# 手动外币请款修复发布

适用服务 `cashier-payment`，目录 `/www/wwwroot/cashier-payment-archive`。本次需求将地区排除限制在钉钉中间库拉取入口；工作台、每日应付和导出展示已录入且有权限的记录。

## 发布

1. 核对线上旧提交、远端目标提交、跟踪文件无未提交变更；保留线上现有未跟踪备份。
2. 读取服务进程环境与工作目录确认真实数据库路径。停止服务，通过 SQLite backup API 备份数据库，核验 `PRAGMA integrity_check`，同时备份旧 `frontend/dist` 和旧提交号。
3. 切到已通过完整后端、前端测试和构建的提交，执行 `npm run build`。依赖未改变，可使用现有环境。
4. 启动服务；启动迁移只为 `payment_requests`、`payable_history_versions` 各新增可空 `payable_item_key` 列，不改写历史金额或审批状态。新手工和 Excel 请款按分期建立稳定标识，更新及结转沿用。
5. 核对服务 active、首页 HTTP 200、新资源文件名及最近服务日志；页面验证新增时可选 USD/MXN、中间库默认“可导入”、手工墨西哥 Sheet 可见。读取生产汇率表核对实际汇率和日期。

## 数据核对

附件 `美金需支付.xlsx` 对应 USD 45,567.18、3,600、3,600，总计 USD 52,767.18。后两笔审批单号相同，但摘要分别第 11、12 期且付款日期不同。检查现有尝试行后再补录，避免创建重复条目。更正 CNY 误标的美元款时采用原金额不变的币种更正，不能按人民币金额换算。保留付款、审批及审计历史。整理不完整或重复行需使用产品版本和可恢复删除流程。

## 回滚

停止服务，切回备份记录的旧提交并恢复旧 dist，再启动。两列新增字段允许旧代码忽略，因此仅回滚代码时通常无需恢复数据库。若需恢复数据，先另存回滚前数据库，并确认备份后的用户写入已另行保全；不要直接覆盖期间新增财务数据。验证首页、服务日志和原数据。
